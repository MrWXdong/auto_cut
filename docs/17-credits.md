## 2. 积分成本

| 动作 | 积分 |
| --- | --- |
| 脚本生成 | 2 |
| 标题/标签 | 1 |
| 分镜 | 5 |
| 封面/图片 | 10 |
| 1 分钟 ASR | 5 |
| 1 分钟 TTS | 8 |
| 渲染 | 20 |
| LoRA 训练 | 300 到 500 |
| 批量任务 | 50 |

草稿、标准、高质量档位会乘 0.5、1、1.5。

## 3. 扣减流程

```text
提交任务 -> 预扣积分 -> 任务成功 -> 结算
                     -> 任务失败 -> 退回
                     -> 用户取消 -> 退回
```

实现：

- `credit_accounts`：租户余额
- `credit_ledger`：发放、预扣、结算、退款流水
- 预扣幂等：同一任务重复提交不会重复扣
- 结算差额：实际消耗低于预扣时自动退回

## 4. 自动开通

### 激活码（当前可用）

1. 平台管理员在 `/platform` 生成激活码
2. 客户打开 `/signup`，选择套餐，填写企业和管理员信息
3. 输入激活码，提交
4. 系统创建租户、owner 账号、发放套餐积分
5. 自动登录并进入 B 端

接口：

```text
POST /api/v1/public/signup
```

### 支付回调（骨架）

```text
POST /api/v1/public/checkout
POST /api/v1/public/payments/webhook
```

- `checkout` 创建 pending 订单，返回订单号
- 支付渠道回调时带 `X-Payment-Secret`
- 回调 `paid` 后自动创建租户、owner 和积分
- 重复回调幂等，不会重复开通

微信/支付宝/Stripe 接入时，只替换渠道下单和验签逻辑，订单与开通流程不变。

## 5. 安全

- 平台管理员和租户账号分开
- 平台接口要求 `scope=platform`
- 支付回调必须校验签名或密钥
- 生产环境修改：

```text
AUTOCUT_AUTH_SECRET
AUTOCUT_PLATFORM_ADMIN_PASSWORD
AUTOCUT_PAYMENT_WEBHOOK_SECRET
AUTOCUT_SEED_DEMO_TENANT=false
```
