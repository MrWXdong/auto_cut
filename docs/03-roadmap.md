# 开发路线图

目标：六周内做出可演示、可部署、可写进简历的完整系统，而不是一个只能在本机跑的脚本。

## 第 1 周：引擎与媒体节点

- 工作流 DAG、执行器、注册表、检查点
- 节点：探测、抽音频、裁剪、多规格导出
- 命令行跑通一条完整流程
- 单元测试覆盖 DAG、重试、续跑

验收：给一个本地视频，输出三个规格的成片。

## 第 2 周：AI 节点与评测集

- ASR 节点（faster-whisper）
- 字幕生成与烧录
- LLM 选段节点，输出结构化片段和理由
- 评测集 v0：30 条素材，标注高光段
- 指标脚本：合格率、召回率、成本

验收：一条 30 分钟素材产出 5 条候选片段和字幕。

## 第 3 周：服务化

- PostgreSQL 表结构与迁移
- Redis 队列与 Worker
- 任务创建、查询、取消、重试接口
- 节点事件落库
- 幂等键与租户字段

验收：API 创建任务后，重启服务任务状态不丢。

## 第 4 周：Web 闭环

- 上传、任务列表、任务详情三个页面
- 轮询或 SSE 展示进度
- 产物预览与下载
- 错误提示和空状态

验收：浏览器完成上传到下载全流程。

## 第 5 周：部署与运维

- Docker 镜像与 Compose
- 云服务器部署、Caddy 反代、HTTPS
- 对象存储接入
- 日志、健康检查、备份
- 压测：2 个并发任务下的接口延迟

验收：公网可访问，服务器重启后任务可恢复。

## 第 6 周：评测、文档与求职材料

- 评测报告：改版前后对比
- 架构图、演示视频、README
- 简历项目描述与面试问答清单
- 技术博客一篇

验收：能在 30 分钟内讲清楚项目，回答评测、成本、并发、失败恢复四类问题。

## 每周固定动作

- 周一：确定本周唯一目标
- 周三：跑一次端到端，记录卡点
- 周五：更新文档和指标，提交可演示版本

## 风险与应对

| 风险 | 应对 |
| --- | --- |
| 范围膨胀 | 每周只加一个能力，P2 功能一律延后 |
| 模型效果不稳定 | 先做评测集，再调 Prompt |
| 视频处理吃内存 | 限制并发，按分辨率分级 |
| 部署成本超预期 | 先用按量对象存储，渲染跑在单机 |
| 求职时间紧 | 第 4 周即可开始投递，边面边补 |
